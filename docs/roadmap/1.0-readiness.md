# Doqs 1.0 readiness

Status after 0.9.0: **not declared 1.0-ready.** This document records the contracts as implemented, the evidence for each, and the blockers that remain. It is an inventory, not a feature roadmap: 0.9 added interactive playgrounds; the next planned minor is 0.10 (source-driven authoring), then the 1.0 release-readiness review.

## Playgrounds (0.9)

- **Contract.** `::playground[id]` + `DoqConfig.playgrounds`. Controls are explicit (`boolean`, `string`, `number`, `select`) and bind by the component's _public_ input name with `createComponent({ bindings })`, so aliases, transforms, required and signal inputs work without private Angular metadata. Outputs are observed with `outputBinding`.
- **Lifecycle.** A control change updates the live component. Reset and a definition change recreate it. Expanding moves the same instance into a native modal `<dialog>`.
- **Not verified / limits.** Overlays appended to `<body>` render below the dialog; controls are not inferred from `doq-api` metadata; object-graph inputs need a wrapper component; screen-reader output was not tested.
- **Adoption findings (Angular Movement `4e71e2f`).** `MoveEnterDirective` is an attribute directive that plays once in `ngOnInit` and exposes no outputs, so the wrapper component re-creates its target element for each input combination and offers its own `played` output. Representable with the public contract; no Doqs change was needed. `pnpm verify:adoption` now proves the live playground against the real checkout.
- **Release finding.** The 0.8.0 release never ran: its eligibility job imported `typescript` before installing dependencies. Fixed and covered by a regression test in 0.9; 0.8.0 reaches npm only if the release workflow publishes it after the merge (npm served 0.7.0 when this was written).

## Guarantees

- **Routing.** `<basePath>/<slug>`; `index.md` represents its folder; invalid slugs and duplicate public routes throw naming the files; the first segment `v` is reserved only when versioning is on. Unknown URLs are 404 on static hosting.
- **SSR/SSG.** Every page prerenders and hydrates with no console errors or warnings (E2E fixture enforces this on every test); `docs:check` validates routes, heading ids, TOC fragments, links and canonicals offline on both showcases and the official site.
- **Search.** Optional, static (Pagefind); index holds exactly the documentation pages at canonical URLs (contract tests); search code loads on first query.
- **Versioning.** Optional; archives are independent folders; the current version has one URL per page.
- **API generation.** Deterministic, owns only `--out`, never executes project code.
- **Theming.** `--host-docs-*` tokens only; no global `html`/`body` rules.
- **Determinism.** `doqDeterministicMarkdown()` contains an upstream race; it does not fix it, and Doqs makes no claim that upstream is fixed.
- **Release.** Version-driven, gated by CI on `main`; npm Trusted Publishing with provenance; no token; the tarball CI verified is the tarball published.

## Compatibility policy

Before 1.0, minors are additive: no removal or incompatible change of anything in the stable list without a deprecation first and a changelog entry. `pnpm verify:public-api` enforces the declaration part against the 0.7.0 baseline (removed exports, retyped members, changed signatures, new required interface members). After 1.0: SemVer: breaking changes only in majors; deprecations live for at least one minor; peer ranges widen only after the compatibility matrix passes for the new version; Node support follows the Node.js release schedule with a minor-version notice before dropping a line.

## Known upstream dependencies and limitations

- Analog's Markdown pipeline renders files concurrently with shared heading state (contained by `doqDeterministicMarkdown()`).
- Analog bundles every Markdown file's frontmatter into the first-loaded JavaScript (about 46–52 B gzip per document); no supported way to defer it.
- Importing any value from `@doqs/analog` in an eagerly loaded chunk keeps the documentation components with it (Angular's compiled classes are not tree-shaken away): the official site measured 260,194 B vs 153,034 B gzip of first-loaded JavaScript for its landing, and avoids the cost by loading the whole region as a lazy route (`apps/site/src/app/docs.routes.ts`).

## Release blockers (evidence-based)

1. **Landmark inconsistency.** The document view renders `article` without a `main`, the index view renders a `main`, and `DoqShellComponent` wraps both in a `main` (nested for the index). Hosts without the shell have no main landmark on document pages. Needs a decision (a documented host responsibility, or one consistent landmark strategy) before the surface is frozen.
2. **Eager-import cost of config helpers.** Because `defineDoqConfig`/`provideDoq` share a module with the components, hosts cannot take configuration without the UI. A secondary entry or a side-effect annotation of the compiled classes would fix it; either is a packaging decision for the 1.0 review.
3. **Leaked and ambiguous exports** (table above) need the stable/internal split decided and, for `DoqButtonDemoComponent`, a deprecation.
4. **Unverified environments** (Zone.js, Vite < 8, screen readers) must be either verified or listed as unsupported in the 1.0 documentation.
5. **Deployment state.** The 0.8.0 package and site were not published or deployed from the feature branch; npm and Cloudflare status must be re-checked after the merge (see the verification report).

## Required tests for 1.0

The full `pnpm quality:gate` including `verify:public-api`, `verify:init` and the Angular Movement proof; a re-run of the 0.8 contract against the real consumers; resolution of the blockers above with regression tests; and a post-release check that npm serves the new version and the tarball's declarations match `public-api.report.json`.
