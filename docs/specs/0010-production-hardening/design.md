# Design — 0010 production hardening

## Existing implementation

- Markdown is rendered at build time: the `analogjs-content-file` plugin of `@analogjs/platform` (`content-plugin.js`) parses each `*.md?analog-content-file=true` module in its `load` hook with a process-wide `marked` instance (`getMarkedSetup` is a singleton) configured with `marked-gfm-heading-id`, `marked-mangle` and, for `highlighter: 'prism'`, an `async: true` `marked-highlight` extension. The result, with ids baked in, is the module's string. At runtime `withMarkdownRenderer()` provides `NoopContentRenderer`, which reads headings back out of that HTML for the table of contents. So **the heading ids are decided exactly once, at build time, in that `load` hook**, and the runtime only trusts them. (`MarkdownContentRendererService` exists in `@analogjs/content` but is not what `withMarkdownRenderer()` provides in 2.9.)
- `marked-gfm-heading-id@4.1.4` (the latest release) keeps `slugger` and `headings` as module variables, resets them in a `preprocess` hook, and its `heading` renderer uses them later. `Analog 2.9.2` (latest) and `3.0.0-beta.8` have the same structure; there is no upstream fix and no per-render isolation API.
- `doqRoutes`, the catalog, `DoqDocsComponent` (scroll restoration per navigation id, `popstate` handling), `DoqPageMetadata` (scoped title, description, canonical), the versioning layer, `doq-search`, `doq-api`, the CDP harness and the Playwright config are as in 0.6. `scripts/consumer.ts` builds tarball consumers; `scripts/adoption.ts` builds the Angular Movement proof and, before this change, rebuilt it up to twelve times until the ids were canonical.

## Proposed implementation

**Determinism (DET).**

1. `docs/repro/heading-id-concurrency.mjs` reproduces the race with the real packages, in two forms: interleaved async parses (ids), and Analog's `await parse(); getHeadingList()` pattern (table of contents).
2. `packages/doq/bin/vite.mjs` exports `doqDeterministicMarkdown()`, a Vite plugin (`enforce: 'pre'`). In `configResolved` it finds the resolved plugin named `analogjs-content-file` and keeps its `load` handler (function or `{ handler }`); in its own `load` it answers only `analog-content-file=true` ids, by calling that handler through a promise chain, so files render one at a time in request order and a failure never blocks the queue. Because Analog's plugin is `enforce: 'post'`, ours answers first and Vite never calls Analog's hook a second time. No upstream code is copied, no global state is patched, no delay is used. If the plugin is missing it throws with instructions instead of silently doing nothing. The `.d.mts` declares a structural plugin type, so the package takes no dependency on Vite. Both showcases and the adoption proof use it.
3. `scripts/docs-check.ts` + `scripts/docs-check/lib.ts` validate generated output (rules in REQ-003/005). Heading ids are compared with `github-slugger` (the library `marked-gfm-heading-id` uses) applied sequentially to the page's own heading texts, so the check needs no knowledge of which file produced which page and fails on any reordering artefact. Source completeness uses the app's `doq.paths.ts`; `packages/doq/test/unit/docs-route-parity.spec.ts` ties the script's route rule to `doqPrerenderRoute`.
4. `scripts/determinism.ts` builds a stress consumer from the tarball (60 generated documents plus archives, each repeating headings; an asynchronous marked extension added to `vite.config.ts`, which is what Shiki's `codeToHtml` does) K times from clean and compares a heading fingerprint and `docs:check`; `--control` removes the guard and must be detected.

**Compatibility (COMP).** `scripts/consumer.ts --angular=22` rewrites `@angular/*` to `^22`, TypeScript to `~6.0`, drops the unused `vite-tsconfig-paths` (its `tsconfck` supports TypeScript 5 only) and installs with `--config.strict-peer-dependencies=true`. `scripts/compat.ts` runs a cell: consumer build (which includes `doq-api check` and `doq-search`), `docs:check`, and `playwright.compat.config.ts` + `e2e/compat.spec.ts`. Both Angular 21 and 22 apps in this repository are zoneless (no `zone.js`, no `provideZoneChangeDetection`); the spec asserts `window.Zone === undefined`.

**Browsers (BROWSER).** `playwright.config.ts` gains `firefox` and `webkit` projects limited to the engine-dependent specs; `pnpm test:e2e` still runs the whole suite in Chromium only and `pnpm test:e2e:browsers` runs the two engines. Test-only helpers in `e2e/fixtures.ts`: `expectClipboard` (reads back where `clipboard-read` can be granted), `nextFocusKey` (Safari's default skips links on Tab; Option+Tab on macOS WebKit), `EXPECTED_404_NOISE`. Product fix in `DoqDocsComponent`: track the last scroll position from scroll events and freeze it while a `popstate` traversal is under way (WebKit restores scroll before `popstate`), re-sampled after the document is revealed. CSS: a `forced-colors` block.

**Accessibility (A11Y).** `e2e/hardening.spec.ts` (three engines): reduced motion, 200% text at 320/1280 px (measured on the documentation, not on the host header), forced colours, consumer tokens with axe contrast, drawer by keyboard and focus after Back. Automated: axe in the existing suites. Manual/unverified: screen-reader announcements, real high-contrast mode, 400% browser zoom beyond the 320 px reflow check, WCAG conformance.

**Performance (PERF).** `scripts/perf.ts` measures artifacts (first-loaded JS = entry module plus `modulepreload` chunks referenced by a documentation page, gzip level 9; all JS; stylesheet; search index files; pages; files) against `perf-budgets.json` (`baseline`, `max`, `reason`). `scripts/scale.ts` builds generated fixtures (`scripts/fixtures/docs.ts`, never committed) and reports build durations, byte metrics and median client navigation latency, and with `--check` enforces the per-document growth budget. Durations are reported, never asserted.

**SEO.** Metadata ownership is unchanged; `metadata.spec.ts` (component) pins the lifecycle. `docs:check` and the Python contracts validate canonicals and links in the output.

**CI.** `ci.yml` gains `docs:check` and `perf:check` in the build job, and jobs `e2e-browsers`, `determinism`, `compat` (matrix 21/22) and `scale`. `release.yml` and `deploy-site.yml` are untouched; release still waits for the whole CI run.

## Tradeoffs and alternatives

- **Runtime queue around `ContentRenderer` (built, then removed).** A first remediation serialized `ContentRenderer.render` in the docs component. It was reverted after reading the code showed that `withMarkdownRenderer()` provides `NoopContentRenderer`: the race is in the build-time Vite hook, so a runtime queue fixed a path no standard configuration uses. The unit evidence for it was not kept.
- **A marked extension with per-parse state** (`markedOptions.extensions`, a `heading` renderer keyed by `this.parser`) would isolate state without serializing, but needs a slugger: shipping `github-slugger` as a dependency for a Node-only helper was rejected (no new runtime dependency, PERF-05), and re-implementing its Unicode rules risks different ids from the published fragments.
- **Replace Analog's plugin / copy its renderer / `patch-package`:** forbidden by the task and fragile.
- **Wait for upstream:** none of 2.9.2, 3.0.0-beta.8 or `marked-gfm-heading-id@4.1.4` fixes it. The guard is a containment at the plugin boundary, not an upstream fix, and the report says so. Hosts that do not add the plugin still need `docs:check` to catch a bad build.
- **Make the guard automatic.** Doqs cannot inject a Vite plugin from `doqPrerenderRoutes()`; adding it silently to every config would also be a breaking behaviour change. It is opt-in and documented; `docs:check` is the safety net.
- **Per-document metadata lazy loading.** Analog bundles every file's frontmatter and loader into the first-loaded JavaScript through its generated content list; deferring it needs a custom loader (unsupported). Documented with a measured slope and a guardrail instead.
- **Shipping `docs:check` in the package.** Useful to hosts, but it needs `github-slugger` and would widen the public surface; kept as a repository tool for now.
- **Running the full suite in Firefox/WebKit.** Roughly 3x CI time for engine-independent logic; the focused list in `playwright.config.ts` keeps feedback quick.
