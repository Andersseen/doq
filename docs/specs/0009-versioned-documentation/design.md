# Design — 0009 Versioned documentation

## Existing implementation

`doq-paths.ts` normalizes `{ contentDirectory, basePath }` and builds Analog prerender routes. `doq-catalog.ts` lists documents with `injectContentFiles` filtered by `/content/<dir>/`, `doq-routes.ts` has one index and one catch-all document matcher, `doq-docs.component.ts` loads Markdown through Analog's slug-keyed `injectContentFilesMap`, and the search service calls Pagefind without options. Navigation, breadcrumbs and pagination all derive from the one catalog.

## Proposed implementation

- `doq-versions.ts` (pure, build-safe): types, `normalizeDoqVersioning`, `getDoqVersions` (current first, then archives in configured order, `basePath` of an archive = `<basePath>/<segment>/<id>`), `doqVersionLinks` (switch destinations from per-version slug sets), `assertDoqSlugNotReserved`, `doqCanonicalUrl`, `DOQ_VERSION_FILTER`.
- `normalizeDoqPaths` returns `versioning` only when configured, so the unversioned shape is unchanged. `doqPrerenderRoutes` flat-maps versions into `[index, content route]` pairs.
- `doqRoutes`: one pair of routes (index + document matcher) per archive carrying `data: { doqVersion }`, then an unknown-version matcher (`<base>/<segment>/…` → docs component with `doqUnknownVersion`), then the current pair whose document matcher rejects the reserved prefix. Separate Route objects per version mean a component is never reused across versions, so every version-dependent value is fixed at construction.
- `injectDoqDocuments(config, versionId?)` filters by the version's own directory; `injectDoqCatalogs` gives all catalogs to the selector; `injectDoqVersion` reads route data.
- `DoqDocsComponent`/`DoqIndexComponent` use the version's `basePath`/`contentDirectory` for links, sidebar root, breadcrumb, content-map lookup and not-found, add `data-pagefind-filter` and a notice, and pass `[version]` to the search component only on versioned sites.
- `DoqVersionSwitcherComponent`: `<details>` + list of `routerLink`s, produced from `doqVersionLinks`; sidebar (so it is also in the drawer), top bar when `sidebar: 'hidden'`, index top bar.
- Search: `DoqSearchService.search(query, bundle, basePath, versionId?)` checks `pagefind.filters()` for the version (else `DoqVersionNotIndexedError`) and passes `{ filters: { doqsVersion } }`.
- `DoqPageMetadata.setCanonical` manages only a Doqs-owned `<link rel="canonical" data-doq-canonical>`.
- Fixtures: Showcase A/B archives with their own older API fixtures generated by `api:v1`; `scripts/consumer.ts --unversioned`; adoption clones upstream tag `v0.9.0`.

## Tradeoffs and alternatives

- Separate Route objects per version instead of one matcher with a version parameter: slightly more routes, but no cross-version component reuse and no reactive version state.
- A native `<details>` of links instead of a `<select>`: every destination is a prerendered URL, middle-click and no-JS work, and arrow keys cannot navigate by accident (a `<select>` fires `change` on arrow keys in some browsers). Costs a little CSS.
- Pagefind filter on the article instead of one index per version: one index, one bundle, native filtering at query time. The cost is that a stale index with no archive pages must be detected, hence `filters()`.
- No `/latest` alias or redirect: keeps existing URLs and avoids duplicate content.
- No canonical link by default: Doqs does not know the site origin; an optional `canonicalOrigin` instead of hard-coding or guessing.
- No snapshot helper: copying a folder and regenerating the API reference with `doq-api` is short, explicit and already deterministic.
- Archive frontmatter is in the bundle (Analog content list); bodies stay lazy. Excluding archive metadata would need a custom Analog loader and is not worth it for 0.6.
